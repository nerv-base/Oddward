# 架构

本文描述当前产品代码。开发边界见 [AGENTS.md](../AGENTS.md)，命令与发行流程见[构建文档](building.md)。

## 入口与依赖

产品入口为 `cmd/launcher`。安装版由 `cmd/stub` 构建的 `Oddward.exe` 选择版本目录，再运行其中的 `oddward-launcher.exe`。

```text
cmd/launcher
  ├─ internal/launcher/system → 领域包
  ├─ internal/launcher        → UI、输入、副作用调度
  └─ internal/launcher/state  → 纯状态规则
```

依赖单向向下。`state` 不访问文件、网络、时钟、goroutine 或 UI 框架；`launcher` 通过最小接口使用系统能力；真实实现由 `system` 提供并在入口注入。

## 主界面数据流

输入经 `Shell.Dispatch` 进入 reducer，产生新模型和副作用。后台工作携带 context 与任务 token，将结果写入有界 channel；下一帧在 UI 线程再次分派事件。过期结果由 reducer 丢弃，后台不直接修改界面。

颜色和尺寸集中在 `internal/launcher/view.go`，强调色使用 `s.tone()`。共享控件放在 `controls.go`。素材以 contain 方式呈现，不假设宽高比；无障碍标签、高对比度及减少动态效果应覆盖每个可交互页面。主页体力卡内嵌官方「本性像素」「都市活力」图标，版权与来源见 `THIRD_PARTY_NOTICES.md`。

应用图标统一来自 `internal/branding`：主窗口通过 MyGo `SetIcon` 设置任务栏图标，导航栏使用单色 SVG，WPF 通过项目资源引用同源图像。两个 Go 入口链接已提交的 Windows/amd64 COFF 图标资源，安装器直接使用同一 ICO；修改 ICO 后用 `scripts/update-icons.ps1` 再生成 COFF。

## 国服登录

`internal/cnlogin/session` 编排配置加载、HTTP 登录、准入、身份投递和窗口生命周期。相关子包各自负责一项能力：

- `launch`：安装和 SDK 兼容性检查、单实例约束、启动环境、游戏进程身份。
- `sdkhost`：SDK 管道、宿主窗口和原生回调。
- `elevatedipc`、`broker`：受限宿主启动、私有 IPC、身份校验及请求转发。
- `laohu`、`bootcfg`、`cnproto`：登录客户端、配置解析和 SDK 消息编码。
- `accounts`：DPAPI、私有目录权限及账号保存事务。
- `loginui`：与 WPF 助手的有界帧通信。

主 UI、WPF、账号库和 HTTP 登录均为普通权限。受限宿主只持有游戏与 SDK 会话，不接受任意命令、账号文件或任意进程操作。窗口嵌入仅作用于本次会话的登录窗口和欢迎横幅，核对进程身份、窗口、隐藏状态与 DPI 后才完成绑定；WPF 等待请求确认及原生关系检查后显示。

登录层优先使用原生子窗口，移动由 Windows 随父窗口处理，缩放由窗口事件同步。DPI 不匹配时回退为从属窗口。游戏主 HWND 销毁或切换时重建自己的隐藏窗口，未提交表单只在内存中保留。

短信冷却以客户端为唯一状态源：有效请求开始即消费 60 秒，错误不返还，切页或重开不重置。界面刷新保留输入和选择状态。

主页选定的账号就是本次登录使用的账号。SDK 请求登录时，若公告已确认且已保存账号，会话直接用最近使用的账号完成校验、准入和身份投递，不再打开登录窗口；凭据失效、服务拒绝或需要官方环境时回退到账号列表窗口并显示原因，由用户决定下一步。首次公告确认后仍停留在账号列表，等用户自己点「登录」。

身份投递成功后显示欢迎横幅：会话换一个只带 `Banner` 的 `welcome` 快照给一个独立的助手进程（不占用登录窗口的通道），WPF 在游戏客户区顶部居中显示「<账号>，欢迎登录」，左侧是黑白的 Oddward 标记（矢量几何，取自 `internal/branding/symbol.svg`），淡入 220 ms、停留 2.4 s、淡出 380 ms 后自行退出；减少动态效果时跳过淡入淡出，只保留停留时间。横幅不获取焦点、不拦截鼠标、不进入任务栏，也不改变登录窗口的关闭计数。`welcome` 快照必须携带非空且不超过 256 字节的 `Banner`，其它屏幕不得携带；横幅启动失败不影响已经完成的身份投递。

身份投递获得原生 ACK，且账号保存或回滚结束后关闭登录窗口；自动登录没有打开窗口时直接结束本次 SDK 请求。SDK 会话仍可回答后续查询。管道断开代表观察丢失，不能当作游戏已退出；只有实际进程退出才结束宿主生命周期。

## 本地数据库

结构化业务数据统一存放在 `%LOCALAPPDATA%\Oddward\oddward.db`；用 `--data-dir` 指定数据目录时改为该目录下的 `oddward.db`，与默认库互不混用。数据库不放在游戏安装目录，也不随 `app-X.Y.Z` 版本目录删除。连接、事务、迁移、备份与完整性检查由 `internal/database` 提供，业务规则仍留在各领域包。

数据库开启 WAL、外键约束与 `synchronous=FULL`。每个进程只有一个写连接，写事务以 `BEGIN IMMEDIATE` 开始；读连接可以并发，`busy_timeout` 让偶发争用排队而不是直接失败。WAL 是库级设置，写进文件头；外键、超时与同步级别是每连接设置，读写两个池都会应用。迁移脚本内嵌在二进制中，按 `user_version` 顺序应用并记录校验和；升级前先写一份 `backups/` 快照，文件版本高于当前程序时明确拒绝启动。关闭连接时执行 WAL checkpoint。

表按领域划分，时间戳统一存 Unix 纳秒（零值存 NULL），抽卡记录时间存毫秒以对齐记录身份 `(角色, 卡池, 物品, 时间, 保底)`。图片、视频、游戏资源等大文件仍在文件系统中，数据库只保存索引、摘要与状态；路径与摘要校验仍在读取侧执行。

旧版本的 JSON 文件保留为镜像。`compat_mirrors` 按领域与路径逐文件记录本版写出的摘要；启动时只要有一个镜像的摘要与磁盘文件不符（或文件已消失），就说明旧版本运行过并改过数据，导入器先把文件内容收敛进数据库再继续，因此升级后回退旧版、再升级回来，旧版期间的修改不会丢失。

镜像的写入顺序是个别领域各自决定的，因为「数据库是新值、文件是旧值」和「文件是新值、数据库是旧值」都会让下一次启动读错方向：

- 设置、抽卡档案、签到记录、账号在同一个事务里写文件与行。事务被拒绝时把刚写的文件恢复成上一份字节，所以一次报告为失败的写入不会在下次启动被当成旧版本的修改重新导入。
- 下载任务、安装记录、预下载记录先提交行、再发文件。导入器比较文件时间与行的 `updated_at`：文件比行旧说明是本版自己的发布失败，以行为准并把文件重写回去；文件比行新才是旧版本的修改，导入文件。账号的镜像目录整体由一个索引文件描述，索引摘要不符才算「别的版本动过文件」，否则同样按行重写文件。

删除同样按「文件集是权威集合」处理：旧版本删掉最后一个抽卡档案或最后一个账号后，目录仍在但集合为空，导入器据此删除对应行；只有整个目录消失时才保留行（此时没有可用的来源，也没有可写回的镜像）。缓存类镜像是可重建的，导入失败只记录错误并保留原文件；设置、账号、抽卡、签到、下载与安装这些用户数据域的导入失败会让启动器以非零状态退出，避免在尚未对账的行上继续写入。

## 数据与网络

非秘密设置、账号索引、抽卡档案、签到记录、下载任务、安装记录与缓存索引都存在本地数据库；设置、账号、抽卡和签到同时保留旧版 JSON 镜像（见上）。账号及塔吉多续期凭据先经 DPAPI 包装并用 AES-256-GCM 加密再入库，主文件、WAL 与 `-shm` 都设置私有 ACL，路径逐级拒绝 symbolic link、junction 与 reparse point。验证码不持久化。塔吉多关联优先读取已保存的游戏渠道凭据换取用户中心会话，换取失败才走短信登录；两条路径共用同一续期凭据存储，不额外保存游戏令牌副本。删除账号会一并删除其关联凭据，解除塔吉多关联不删除本地抽卡档案。签到记录按「账号 + 角色 + 类型 + 日期」去重、按日期在 60 天后淘汰，同一天重新关联不会重复提交。

抽卡页只展示实际记录，名称不明时保留原始 ID，图标不可用时使用占位。塔吉多官方补充名称优先；官方没有收录的弧盘才读取 BWIKI 的公开名称、稀有度和图标，缓存 7 天、只保留这三项显示字段，刷新失败保留旧缓存。读取、导入和导出经系统适配完成，视图只使用档案类型与纯函数。

抽卡图标在界面进程内由四个有界 worker 加载，同一 ItemID 的重复请求合并为一次；解码和缩放离开窗口线程，窗口线程只把结果放进 Bitmap LRU 并刷新。档案加载完成后先按首屏可见行数为三个卡池预取图标，其余记录随滚动按需请求，切换角色或离开页面会取消尚未交付的请求。`internal/gamemedia` 的磁盘缓存命中已验证文件时直接返回旧图，条目不新鲜时先显示旧图再后台重新验证，访问时间合并成批量更新而不重写索引。解码后的缩略图按 ItemID 与解码边长存到 `cache/wish-thumbs`（30 天过期、约 24MB 淘汰目标），重启后直接读取像素；损坏、过期或尺寸不符的文件一律当作未命中，仍按原流程重新取值。

HTTP 使用统一网络设置。媒体下载限制来源、重定向、大小及像素数。从国服官方启动器公告页发现原版白色 Logo，从国服官网封面发现标语。显式指定的本地 Logo 优先，官方 Logo 读取失败时界面显示游戏名。版本名只接受桌面公告数据中的《异环》命名版本公告，不根据日期猜测资源，也不切换 Global 或 Taiwan 来源。已验证的标语图片和元数据单独写入品牌缓存：元数据是 `branding_record` 一行，图片按内容摘要命名，行里的摘要必须与文件名一致，读取时不匹配就当作无效记录。遇到人机验证停止自动流程，由用户在官方客户端完成。

普通模式未指定本地背景时，[启动器媒体客户端](../internal/launchmedia/media.go) 先读取本地已验证的 `bg.mp4` 与封面，窗口立即应用封面并取强调色；封面优先使用 `poster-preview.jpg`（不超过 1920×1080 的 JPEG），缺失时回退全尺寸 `poster`。随后按国服官方启动器的 `Version.ini` 和 `AllFiles.xml` 异步刷新，仅在 ZIP 与文件的大小、校验和、文件类型通过检查后原子替换，并且只返回变化的资产。视频固定写入 `bg.mp4`，刷新后用 `OpenData` 从内存打开新播放器，再关闭旧播放器，避免 Media Foundation 持有文件句柄阻止覆盖；封面变化时同时生成预览。刷新失败时各自保留已有缓存。媒体获取由后台执行，窗口线程只应用结果与控制播放。指定本地背景参数时使用本地素材。

公告通过系统适配层读取。后台先送回数据库里上次的列表快照，再刷新官网，失败时保留快照并提供重试。缓存按来源白名单校验，有独立的列表、封面和正文容量上限。封面按 URL 复用，正文在线读取失败时使用同一 URL 的本地副本。UI 线程每 6 秒推进首页推荐封面，鼠标停留、键盘聚焦、离开主页、打开弹窗或减少动态效果时暂停。

## 签到、游戏信息与游戏数据

签到页复用同一条塔吉多关联，不新建登录层：关联、续期凭据与 `Session` 都来自抽卡页那套实现，`internal/tajiduo` 只增加签到与 `roleHome` 的协议函数。游戏签到按角色提交，社区签到按账号提交，两者各自读写记录、各自显示结果，一种成功不会被当成另一种成功。游戏侧的 `todaySign` 只有 `gameId`，不能证明某个角色今天签过：它只在写入之后用来消解「已签到」的分歧，不会代替该角色自己的记录。

`internal/checkin` 保存逐日记录与两个自动开关，位于本地数据库的 `checkin_records` 与 `checkin_auto` 表（镜像仍写在 `%LOCALAPPDATA%\Oddward\checkin`），只写账号 ID、角色 ID、日期、结果和一句说明。写入先记 `pending` 意图再发请求，因此“请求已发出但结果未知”可以跨重启识别：这种记录在刷新时向服务器核实，核实前既不显示为完成，也不会被自动重试。交给服务器的证据（`todaySign` 等状态）优先于本地推断；服务器称已签而状态未确认时记为待核实。

每日签到由界面上的开关逐个启用，默认关闭，只在启动器运行期间按天执行一次，不注册计划任务。唯一触发点是用户点击「启动游戏」。它与启动流程并行，签到状态刷新成功后才尝试提交。打开签到页、启动器空闲和演示模式都不会触发。账号 ID 随请求下传：过期页面或已切换账号的请求会被拒绝，不会用当前凭据替另一个账号签到。多个启动器实例通过记录目录上的独占锁互斥，抢不到锁的操作直接报忙。

游戏信息面板只显示服务器返回的字段：本性像素、都市活力、每日活跃度、周本剩余，以及角色名、等级、鉴别等级等。角色头像是按 `roleHome` 返回的头像 id 从官方社区 CDN 读取的公开图片，失败时回退到姓名首字。接口只提供当前值与上限，没有提供恢复时间、备用池、溢出资源或派遣数据；主页的本性像素卡片按 6 分钟/点计算下一点与回满时间，卡片右上角可手动刷新，备用体力不推算，轨外之境不展示。读取由用户主动刷新，失败时保留上次成功快照并标注失败原因，不在后台轮询。

「游戏数据」页复用同一条 `roleHome` 快照，增加角色收集、区域探索、房产与载具概览；它不另发详情请求，也不编造未返回的字段。进入页面或主页时读取一次，手动刷新才会再次读取。

## 游戏资源规划

未定位到游戏时，点击主页的「下载游戏」打开居中的「选择安装路径」窗口。选中空目录后生成安装计划，显示实际的下载量、磁盘空间，以及随后会安装的运行组件。「定位游戏」链接用于选择已有安装。定位有效安装后，主按钮显示「启动游戏」或已确认的「更新游戏」。主页的主操作与事件由 `state` 使用同一个下载状态投影；正式更新与预下载在规划完成后直接开始，空间不足时主按钮停在「空间不足」等用户换目录或清理，首装计划的确认仍在路径窗口里完成。

主页右下角只有胶囊本身：未开始任务且已是最新版本时显示「启动游戏」，有正式更新时显示「更新游戏」，点击即开始下载；进度、暂停与继续都收进同一颗胶囊。检测到预下载时，胶囊左侧出现「预下载」chip（进行中显示百分比，可暂停或继续）；悬停胶囊只展开一行摘要与「取消任务」。预下载可用、待核对、可应用或失败时，chip 分别给出对应动作。不再有常驻下载面板，也没有单独的详情按钮。

胶囊右侧的齿轮打开单页「游戏」面板：安装目录、当前与可用版本、重新校验和打开安装文件夹，预下载管理跳转到启动器设置。胶囊上方是账号行，列出下次登录会使用的已保存账号，可切换、重命名或删除。左侧栏齿轮打开独立的「启动器设置」，分为常规、外观、下载与网络、文件、关于：常规控制关闭窗口时最小化到托盘、启动时检查 Oddward 更新；外观控制背景动画、减少动态效果和强调色跟随主视觉；下载与网络只保留全局限速和代理/镜像，另列下载暂存目录、磁盘预算与任务维护（暂停、继续、取消、检查更新、预下载核对/应用/清理），并发、连接数与缓存上限已从界面和存储中移除，自动恢复与差分更新始终开启；文件页显示设置与账号目录、游戏安装目录；关于页包含版本、检查更新和项目链接。关闭窗口默认隐藏到托盘，托盘菜单可恢复窗口或退出。网络表单切换分类时保留未保存的输入。开发者状态预览通过 F8 打开。

[资源规划器](../internal/gameres/plan.go) 接收已核对的国服配置、清单和本地状态，生成 `baseTag` 安装计划。计划区分已安装且验证通过的文件、已验证缓存、完整下载和满足能力条件的差分链，并附带同卷空间预算和逐目标回退来源。

[系统适配层](../internal/launcher/system/download_backend.go) 只访问配置的官方 CDN，使用已校验的投递清单生成范围下载任务。[下载引擎](../internal/gamedl/engine.go) 在同一个安装锁下保存断点，校验整文件的字节数和 MD5 后发布缓存。[安装事务](../internal/gameinstall/txn.go) 把旧文件留在同卷备份，发布 Oddward 安装记录后才能确认新版本。启动前会检查有无未完成的提交。现有安装的接管和校验只读取官方状态，在 Oddward 数据目录记录结果。

首次下载会写入游戏资源及两份引导配置。登录与启动还需要官方运行组件（登录器可执行文件、SDK 桥、渠道配置和 patcher 元数据），这些文件不由游戏资源清单提供。[运行组件包](../internal/launcherfiles/launcherfiles.go) 在资源校验后读取厂商公开的版本清单，按逐文件 ZIP 下载 10 个必需文件并校验大小与 MD5，先暂存在下载工作目录；安装提交成功后才发布到安装目录并写入 SDK 桥指针，因此提交前不会污染目标。仓库不打包任何官方二进制。启动预检随后要求这些文件、`Config.ini` 中的 OneAppId 以及兼容的官方登录 SDK。用户可为首装选择另一块本地卷暂存下载，规划分别检查暂存卷和安装卷容量。提交把已验证文件复制到目标卷，再按同卷事务发布。跨卷暂存路径随任务保存在本地，重启会重新校验路径和清单。

差分重建只使用通过整文件校验的安装源和未压缩 HDIFF13 补丁。差分始终开启，不再提供用户开关；补丁不可用或产物校验失败时，按目标重新检查空间和完整资源来源，再通过原事务提交。预下载支持暂存、正式发布后的清单核对、补下载和提交。官方预发布查询路径仍待观测，当前公开入口按未开放处理。

## 自更新

正式安装按版本目录存放文件。更新先验签、逐文件校验，再完成可恢复的版本切换；不会在未完成校验时覆盖旧版本。启动桩可在新版本启动失败后回退。数据库无法打开或升级失败时程序以非零状态退出且不写 `.healthy`，启动桩据此回退到上一个版本；回退期间的数据交换由镜像与导入器完成。

开发构建或未配置更新公钥时禁用更新。镜像仅影响下载地址，不跳过签名、哈希或路径检查。签名私钥不进入源码和构建输出。

## 依赖与许可

Go 模块固定在 `go.mod` / `go.sum`，.NET SDK 固定在 `compat/loginui/global.json`，自包含运行库固定在项目文件中。当前主要依赖为 MyGo、purego、go-text/typesetting、golang.org/x 系列包，以及纯 Go 的 `modernc.org/sqlite`（静态链接 SQLite，不需要额外的 DLL 或运行库）。

版本、来源和完整声明统一维护在 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 与 `licenses/`。新增依赖前需核对许可证；发行构建会携带这些声明。官方游戏 SDK 与媒体不纳入源码或发行包。

## 静态检查

常规测试命令见 [CONTRIBUTING.md](../CONTRIBUTING.md)。结构调整或删除代码时，使用固定工具版本补充检查：

```powershell
pwsh -File scripts/go.ps1 run honnef.co/go/tools/cmd/staticcheck@v0.8.2 -checks=U1000,SA*,S1* ./...
pwsh -File scripts/go.ps1 run golang.org/x/tools/cmd/deadcode@v0.52.0 -test ./...
pwsh -File scripts/go.ps1 mod tidy
```

分析结果需要结合入口与测试用途判断；不要仅凭工具报告删除被其他入口使用的代码。
