# 架构

本文描述当前产品代码。开发边界见 [AGENTS.md](../AGENTS.md)，命令与发行流程见[构建文档](building.md)。

## 入口与依赖

产品入口为 `cmd/launcher`。安装版由 `cmd/stub` 构建的 `Oddward.exe` 选择版本目录，再运行其中的 `oddward-launcher.exe`。

```text
cmd/launcher
  ├─ internal/launcher/system → 领域包
  ├─ internal/launcher        → UI、输入、副作用调度
  └─ internal/launcher/state  → 纯状态规则
```

依赖单向向下。`state` 不访问文件、网络、时钟、goroutine 或 UI 框架；`launcher` 通过最小接口使用系统能力；真实实现由 `system` 提供并在入口注入。

新增业务规则放在 `state`，新增副作用定义为 `Effect`，需要真实系统时在 `launcher` 定义接口、在 `system` 实现。领域能力放在对应的 `internal` 包中，不把文件、进程或网络操作放入视图。

## 主界面数据流

输入经 `Shell.Dispatch` 进入 reducer，产生新模型和副作用。后台工作携带 context 与任务 token，将结果写入有界 channel；下一帧在 UI 线程再次分派事件。过期结果由 reducer 丢弃，后台不直接修改界面。

颜色和尺寸集中在 `internal/launcher/view.go`，强调色使用 `s.tone()`。共享控件放在 `controls.go`。素材以 contain 方式呈现，不假设宽高比；无障碍标签、高对比度及减少动态效果应覆盖每个可交互页面。

应用图标统一来自 `internal/branding`：主窗口通过 MyGo `SetIcon` 设置任务栏图标，导航栏使用单色 SVG，WPF 通过项目资源引用同源图像。两个 Go 入口链接已提交的 Windows/amd64 COFF 图标资源，安装器直接使用同一 ICO；修改 ICO 后用 `scripts/update-icons.ps1` 再生成 COFF。

## 国服登录

`internal/cnlogin/session` 编排配置加载、HTTP 登录、准入、身份投递和窗口生命周期。相关子包各自负责一项能力：

- `launch`：安装和 SDK 兼容性检查、单实例约束、启动环境、游戏进程身份。
- `sdkhost`：SDK 管道、宿主窗口和原生回调。
- `elevatedipc`、`broker`：受限宿主启动、私有 IPC、身份校验及请求转发。
- `laohu`、`bootcfg`、`cnproto`：登录客户端、配置解析和 SDK 消息编码。
- `accounts`：DPAPI、私有目录权限及账号保存事务。
- `loginui`：与 WPF 助手的有界帧通信。

主 UI、WPF、账号库和 HTTP 登录均为普通权限。受限宿主只持有游戏与 SDK 会话，不接受任意命令、账号文件或任意进程操作。窗口嵌入仅作用于本次会话的登录窗口，核对进程身份、窗口、隐藏状态与 DPI 后才完成绑定；WPF 等待请求确认及原生关系检查后显示。

登录层优先使用原生子窗口，移动由 Windows 随父窗口处理，缩放由窗口事件同步。DPI 不匹配时回退为从属窗口。游戏主 HWND 销毁或切换时重建自己的隐藏窗口，未提交表单只在内存中保留。

短信冷却以客户端为唯一状态源：有效请求开始即消费 60 秒，错误不返还，切页或重开不重置。界面刷新保留输入和选择状态。

身份投递获得原生 ACK，且账号保存或回滚结束后关闭登录窗口；SDK 会话仍可回答后续查询。管道断开代表观察丢失，不能当作游戏已退出；只有实际进程退出才结束宿主生命周期。

## 数据与网络

非秘密设置与账号数据分开保存。账号及塔吉多续期凭据使用 DPAPI；验证码不持久化。删除账号会一并删除其关联凭据，解除塔吉多关联不删除本地抽卡档案。签到记录按「账号 + 角色 + 类型 + 日期」去重、按日期在 60 天后淘汰，同一天重新关联不会重复提交。

抽卡页只展示实际记录，名称不明时保留原始 ID，图标不可用时使用占位。读取、导入和导出经系统适配完成，视图只使用档案类型与纯函数。

HTTP 使用统一网络设置。媒体下载限制来源、重定向、大小及像素数。从国服官方启动器公告页发现原版白色 Logo，从国服官网封面发现标语。显式指定的本地 Logo 优先，官方 Logo 读取失败时界面显示游戏名。版本名只接受桌面公告数据中的《异环》命名版本公告，不根据日期猜测资源，也不切换 Global 或 Taiwan 来源。已验证的标语图片和元数据单独写入品牌缓存，采用有限大小、校验和成对原子替换，离线时保留上一份有效记录。遇到人机验证停止自动流程，由用户在官方客户端完成。

普通模式未指定本地背景时，[启动器媒体客户端](../internal/launchmedia/media.go) 按国服官方启动器的 `Version.ini` 和 `AllFiles.xml` 获取 `bg.mp4` 与 `bg_0.png` 或 JPEG 封面。仅在 ZIP 与文件的大小、校验和、文件类型通过检查后更新本地缓存。刷新失败时各自回退到已有缓存。媒体获取由后台执行，窗口线程只应用结果与控制播放。指定本地背景参数时使用本地素材。

公告通过系统适配层读取。后台先送回 `cache/news` 中的上次快照，再刷新官网，失败时保留快照并提供重试。缓存按来源白名单校验，有独立的列表、封面和正文容量上限。封面按 URL 复用，正文在线读取失败时使用同一 URL 的本地副本。UI 线程每 6 秒推进首页推荐封面，鼠标停留、键盘聚焦、离开主页、打开弹窗或减少动态效果时暂停。

## 签到与游戏信息

签到页复用同一条塔吉多关联，不新建登录层：关联、续期凭据与 `Session` 都来自抽卡页那套实现，`internal/tajiduo` 只增加签到与 `roleHome` 的协议函数。游戏签到按角色提交，社区签到按账号提交，两者各自读写记录、各自显示结果，一种成功不会被当成另一种成功。游戏侧的 `todaySign` 只有 `gameId`，不能证明某个角色今天签过：它只在写入之后用来消解「已签到」的分歧，不会代替该角色自己的记录。

`internal/checkin` 保存逐日记录与两个自动开关，位于 `%LOCALAPPDATA%\Oddward\checkin`，只写账号 ID、角色 ID、日期、结果和一句说明。写入先记 `pending` 意图再发请求，因此“请求已发出但结果未知”可以跨重启识别：这种记录在刷新时向服务器核实，核实前既不显示为完成，也不会被自动重试。交给服务器的证据（`todaySign` 等状态）优先于本地推断；服务器称已签而状态未确认时记为待核实。

自动签到由界面上的开关逐个启用，默认关闭，只在启动器运行期间按天执行一次，不注册计划任务。唯一触发点是用户点击「启动游戏」：它与启动流程并行，不等待登录组件，也不因启动失败而回滚；打开签到页、启动器空闲和演示模式都不会触发。账号 ID 随请求下传：过期页面或已切换账号的请求会被拒绝，不会用当前凭据替另一个账号签到。多个启动器实例通过记录目录上的独占锁互斥，抢不到锁的操作直接报忙。

游戏信息面板只显示服务器返回的字段：本性像素、都市活力、每日活跃度、周本剩余，以及角色名、等级、世界等级等。接口没有提供体力恢复时间、溢出资源或派遣数据，界面据此说明不做推算。读取由用户主动刷新，失败时保留上次成功快照并标注失败原因，不在后台轮询。

## 游戏资源规划

未定位到游戏时，点击主页的「下载游戏」打开居中的「选择安装路径」窗口。选中空目录后生成安装计划，并显示实际的下载量和磁盘空间。点击「开始下载」后，任务进度和控制显示在主页的下载区，收起下载区只影响显示。「定位游戏」链接用于选择已有安装，检测到有效安装后主按钮恢复为「启动游戏」。

主页的「游戏设置」使用居中的毛玻璃对话框，在「基本信息」和「下载设置」间切换。左侧栏齿轮打开独立的「启动器设置」页面，在左栏切换「常规」「网络」「关于」。网络表单切换分类时保留未保存的输入。当前版本和启动器更新入口在「关于」。开发者状态预览通过 F8 打开。

[资源规划器](../internal/gameres/plan.go) 接收已核对的国服配置、清单和本地状态，生成 `baseTag` 安装计划。计划区分已安装且验证通过的文件、已验证缓存、完整下载和满足能力条件的差分链，并附带同卷空间预算和逐目标回退来源。

[系统适配层](../internal/launcher/system/download_backend.go) 只访问配置的官方 CDN，使用已校验的投递清单生成范围下载任务。[下载引擎](../internal/gamedl/engine.go) 在同一个安装锁下保存断点，校验整文件的字节数和 MD5 后发布缓存。[安装事务](../internal/gameinstall/txn.go) 把旧文件留在同卷备份，发布 Oddward 安装记录后才能确认新版本。启动前会检查有无未完成的提交。现有安装的接管和校验只读取官方状态，在 Oddward 数据目录记录结果。

首次下载会写入游戏资源及两份引导配置。游戏启动和登录依赖兼容的官方启动组件，空目录下载不包含这些文件。现有启动预检要求安装目录中有官方启动器及其配置，并能找到兼容的官方登录 SDK。用户可为首装选择另一块本地卷暂存下载，规划分别检查暂存卷和安装卷容量。提交把已验证文件复制到目标卷，再按同卷事务发布。跨卷暂存路径随任务保存在本地，重启会重新校验路径和清单。

差分重建只使用通过整文件校验的安装源和未压缩 HDIFF13 补丁。默认允许规划差分，用户可在下载设置关闭；补丁不可用或产物校验失败时，按目标重新检查空间和完整资源来源，再通过原事务提交。预下载支持暂存、正式发布后的清单核对、补下载和提交。官方预发布查询路径仍待观测，当前公开入口按未开放处理。

## 自更新

正式安装按版本目录存放文件。更新先验签、逐文件校验，再完成可恢复的版本切换；不会在未完成校验时覆盖旧版本。启动桩可在新版本启动失败后回退。

开发构建或未配置更新公钥时禁用更新。镜像仅影响下载地址，不跳过签名、哈希或路径检查。签名私钥不进入源码和构建输出。

## 依赖与许可

Go 模块固定在 `go.mod` / `go.sum`，.NET SDK 固定在 `compat/loginui/global.json`，自包含运行库固定在项目文件中。当前主要依赖为 MyGo、purego、go-text/typesetting 和 golang.org/x 系列包。

版本、来源和完整声明统一维护在 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 与 `licenses/`。新增依赖前需核对许可证；发行构建会携带这些声明。官方游戏 SDK 与媒体不纳入源码或发行包。

## 静态检查

常规测试命令见 [CONTRIBUTING.md](../CONTRIBUTING.md)。结构调整或删除代码时，使用固定工具版本补充检查：

```powershell
pwsh -File scripts/go.ps1 run honnef.co/go/tools/cmd/staticcheck@v0.8.2 -checks=U1000,SA*,S1* ./...
pwsh -File scripts/go.ps1 run golang.org/x/tools/cmd/deadcode@v0.52.0 -test ./...
pwsh -File scripts/go.ps1 mod tidy
```

分析结果需要结合入口与测试用途判断；不要仅凭工具报告删除被其他入口使用的代码。
